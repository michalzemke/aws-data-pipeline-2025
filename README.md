# AWS Data Pipeline – aws-data-pipeline Cloud Engineer Technical Assignment

## Project Overview

This project demonstrates an end-to-end serverless data processing pipeline built on AWS using Infrastructure as Code (Terraform).

The solution automatically processes JSON files uploaded to an Amazon S3 bucket. When a new file is uploaded, Amazon S3 triggers an AWS Lambda function that extracts selected patient information and stores the processed data in a separate S3 bucket. All infrastructure is provisioned and managed using Terraform.

---

# Architecture

The solution uses the following AWS services:

- Amazon S3
- AWS Lambda
- AWS IAM
- Amazon CloudWatch Logs
- Terraform

## Processing Flow

```
                Upload JSON file
                       │
                       ▼
         +---------------------------+
         |     Raw Data S3 Bucket    |
         |      input/*.json         |
         +-------------+-------------+
                       │
               S3 ObjectCreated Event
                       │
                       ▼
         +---------------------------+
         |       AWS Lambda          |
         |   Data Processing Logic   |
         +-------------+-------------+
                       │
        Extract:
        • patient_id
        • patient_name
                       │
                       ▼
         +---------------------------+
         | Processed Data S3 Bucket  |
         | processed/input/*.json    |
         +-------------+-------------+
                       │
                       ▼
            Amazon CloudWatch Logs
```

# Solution Components

## Amazon S3

Terraform provisions two S3 buckets.

### Raw Data Bucket

Stores incoming JSON files.

Example:

```
s3://aws-data-pipeline-raw-data-<account-id>/input/patient.json
```

### Processed Data Bucket

Stores processed JSON files generated by Lambda.

Example:

```
s3://aws-data-pipeline-processed-data-<account-id>/processed/input/patient.json
```

# AWS Lambda

**Function Name**

```
aws-data-pipeline-data-processor
```

**Runtime**

```
Python 3.13
```

## Responsibilities

The Lambda function performs the following steps:

1. Receives an S3 ObjectCreated event.
2. Reads the uploaded JSON file.
3. Parses the JSON document.
4. Extracts:
   - patient_id
   - patient_name
5. Creates a simplified JSON document.
6. Stores the processed file in the Processed Data bucket.
7. Writes execution logs to CloudWatch Logs.

### Example Input

```json
{
    "patient_id": "12345",
    "patient_name": "John Nowal",
    "age": 40,
    "city": "Warsaw"
}
```

### Example Output

```json
{
    "patient_id": "12345",
    "patient_name": "John Nowak"
}
```

# IAM Configuration

Terraform creates a dedicated IAM Role for the Lambda function.

## IAM Role

```
aws-data-pipeline-lambda-role
```

The role includes:

### AWS Managed Policy

```
AWSLambdaBasicExecutionRole
```

Allows Lambda to:

- Create CloudWatch Log Groups
- Create Log Streams
- Write execution logs

### Custom IAM Policy

```
aws-data-pipeline-lambda-s3-policy
```

Permissions granted:

- Read objects from the Raw Data bucket
- Write objects to the Processed Data bucket

The policy follows the Principle of Least Privilege.

# CloudWatch Logs

Lambda execution logs are stored in:

```
/aws/lambda/aws-data-pipeline-data-processor
```

Retention period:

```
14 days
```

Each execution logs:

- Lambda start
- Source bucket
- Source object
- Processing status
- Output object
- Errors (if any)

- Input files are valid JSON documents.
- Each JSON file contains:
  - patient_id
  - patient_name
- One file is processed per Lambda invocation.
- Infrastructure is deployed into a single AWS account.
- Terraform state is stored locally for this assignment.

# Challenges

During implementation, the Lambda function automatically created its CloudWatch Log Group after the first execution.

When CloudWatch management was added to Terraform, the resource already existed.

To keep Terraform as the single source of truth, the existing Log Group was imported into the Terraform state:

```bash
terraform import aws_cloudwatch_log_group.lambda_logs \
/aws/lambda/aws-data-pipeline-data-processor
```

# Security Considerations

The solution follows several AWS security best practices:

- S3 Block Public Access enabled
- Server-side encryption (AES-256)
- Least-privilege IAM permissions
- No AWS credentials stored in source code
- Terraform state excluded from Git
- Lambda execution role restricted to required AWS services
