# AWS Data Pipeline - aws-data-pipeline Cloud Engineer Assignment

## Overview

This project implements an end-to-end AWS data processing pipeline using Terraform and AWS serverless services.

The solution uses:

- Amazon S3 for data storage
- AWS Lambda for JSON processing
- AWS IAM for permissions management
- Amazon CloudWatch Logs for monitoring
- Terraform for Infrastructure as Code (IaC)

The pipeline receives JSON files from an S3 Raw Data bucket, processes selected fields using Lambda, and stores the processed output in a separate S3 bucket.

# AWS Resources Created

## S3 Buckets

Terraform creates two S3 buckets.

### Raw Data Bucket

Purpose:

- Stores incoming JSON files.
- Source location for Lambda processing.

Example:
s3://aws-data-pipeline-raw-data-/input/patient.json

---

### Processed Data Bucket

Purpose:

- Stores processed JSON output generated by Lambda.

Example:
s3://aws-data-pipeline-processed-data-/processed/input/patient.json

---

# Lambda Function

Function name:
aws-data-pipeline-data-processor

Runtime:
Python 3.13

Lambda workflow:

1. Receives S3 ObjectCreated event.
2. Reads JSON file from Raw Data bucket.
3. Extracts:

```json
{
  "patient_id": "...",
  "patient_name": "..."
}

4. Writes processed JSON file to Processed Data bucket.

{
  "patient_id": "12345",
  "patient_name": "John Nowak"
}



IAM Configuration

Terraform creates:

Lambda Execution Role
aws-data-pipeline-lambda-role


Permissions:

CloudWatch Logs

Managed policy:
AWSLambdaBasicExecutionRole

Allows Lambda to:

* Create log streams.
* Write execution logs.

S3 Permissions

Custom IAM policy:
aws-data-pipeline-lambda-s3-policy

Permissions:
s3:GetObject
s3:PutObject
s3:ListBucket

The Lambda can:

* Read files from Raw Data bucket.
* Write processed files to Processed Data bucket.



CloudWatch Logs

Lambda logs are stored in:
/aws/lambda/aws-data-pipeline-data-processor

Retention: 14 days

Lambda logs:

* Execution start.
* Input file information.
* Processing status.
* Output location.
* Errors.

Assumptions

* Input files are valid JSON.
* Each file contains:
    * patient_id
    * patient_name
* Processing does not require a database.
* Deployment is performed in a single AWS account.
* Terraform state is managed locally.


Challenges

CloudWatch Log Group Already Exists

Lambda automatically creates its CloudWatch Log Group after the first execution.

Solution:

Imported the existing resource into Terraform:
terraform import aws_cloudwatch_log_group.lambda_logs /aws/lambda/aws-data-pipeline-data-processor


Security Considerations

Implemented:

* S3 Block Public Access enabled.
* S3 server-side encryption enabled.
* Least privilege IAM permissions.
* No credentials stored in code.
* Terraform state files excluded from Git.
